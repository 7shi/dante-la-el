# commentary

Commentary on each canto of the Divine Comedy, generated by an LLM from the Italian text of [dante-corpus](https://github.com/7shi/dante-corpus), together with a line-by-line translation of the whole canto, in Modern Greek (`el`), Esperanto (`eo`), and English (`en`).

> [!NOTE]
> The commentary and translations are machine-generated and have not been reviewed by translators or scholars.

All output is generated with `gpt-6-astra`; the model and the default target language (`el`) are set once, in the [Makefile](Makefile).

The scripts were copied from [dante-commentary](https://github.com/7shi/dante-commentary) (as of commit `cf5a3ab`), which generates the same kind of commentary in Japanese, and adapted here; this directory does not depend on or refer to that repository at run time.

## Output

For each canto, `<code>/<canticle>/<NN>.*` (`<code>` is `el`, `eo`, or `en`):

- `<NN>.md` — commentary: headings per scene or theme, each quoting the key lines as `> N original` followed by `> (translation)`, then discussing their allegory and background; it ends with a closing section (`## Επίλογος — ...` in `el`)
- `<NN>.txt` — translation: one line of the target language per line of the Italian text (blank where still untranslated)

`el-grc/inferno/<NN>.txt` holds a literal Modern Greek translation of Musurus's Greek verse translation of the Inferno ([`texts/grc/`](../texts/grc/)), one line per line of the Greek, which renders the Italian line for line. It has no commentary yet; it is generated with `make generate CANTICLE=inferno SOURCE=grc`. Every target takes `SOURCE=grc` for it, and the checks save their answers in `check/el-grc/`.

Grammar commentaries in English on these sources, quoting the translations of this directory, are in [`grammar/`](../grammar/); their scripts use `scripts/source.py`, `generate.py`, and `fix_quote_blocks.py` of this directory.

## Usage

```bash
make generate CANTICLE=inferno CANTO=1-3
make check-quotes
make fix-quotes
```

`CANTO` takes the SPEC syntax of dante-corpus (`N`, `N-M`, `N-`, `-M`, comma-separated); without it, every canto of the canticle is processed. `check-quotes` then reports the quote marks of the translations that do not follow the original; after fixing them in `<NN>.txt`, `fix-quotes` copies the translations into the quote blocks of every commentary and normalizes them (see below).

Every target takes `LANG=<code>` to choose the target language (`el`, `eo` or `en`, default `el`), e.g. `make generate CANTICLE=inferno LANG=eo`; the output then goes to `<code>/` and `check/<code>/`. Only a `LANG` given on the command line counts: the `LANG` of the environment is the locale and is ignored.

## scripts/generate.py

```bash
uv run scripts/generate.py <canticle> -m MODEL -l CODE -d DIR [-c SPEC] [-s SOURCE] [-r ROUNDS] [--no-think] [--save-usage]
```

argument | description | default
---|---|---
`canticle` | `inferno`, `purgatorio`, or `paradiso` | required
`-m`, `--model` | model name with an optional vendor prefix | required
`-l`, `--lang-code` | language code of the target language; selects its entry in `LANGUAGES` | required
`-d`, `--dir` | output directory | required
`-c`, `--canto` | cantos to process (SPEC syntax) | all
`-s`, `--source` | source text: `it` (the Italian of dante-corpus) or `grc` (Musurus's Greek Inferno, translation only) | `it`
`-r`, `--rounds` | max passes to fill untranslated lines | `5`
`--no-think` | disable thinking output | enabled
`--save-usage` | record usage for any model (by default only `openai:` and `gpt-` models are recorded) | -

Each canto is processed in two steps:

1. **Commentary**: the Italian text, numbered line by line, is sent with the commentary prompt. If `<NN>.md` already exists, this step is skipped.
2. **Translation**: the `> N original` / `> (translation)` pairs quoted in the commentary seed the translation; a pair whose quoted original does not match the corpus line exactly is dropped. The original and the translations so far are then sent on alternating lines, with a placeholder on each untranslated line, and the model fills in those lines only. A filled line is rejected if it still holds the placeholder, copies the Italian, or has no letter of the target language in it; rejected lines are retried in the next round, up to `--rounds` rounds.

`<NN>.txt` is saved after every round. If it already exists, it is read back and only the missing lines are filled, so an interrupted run resumes where it stopped.

With `-s grc`, the source is the verse of `texts/grc/` (read by `scripts/source.py`, without the headings, arguments, page comments and line numbers; every canto has the line count of the Italian), and only step 2 is run: every line starts untranslated. Its prompt asks for a literal translation instead of a readable one: every word rendered, and the word order, the constructions, and the tenses of the original kept as far as the line stays correct and reads as the original means. A filled line is also rejected if it contains polytonic letters (a copy of the Greek).

Both prompts are written in English, with the language name filled in. Each language code has an entry in `LANGUAGES` in the script:

- `name`: the name of the language, written into the prompts (`Modern Greek` for `el`, `Esperanto` for `eo`, `English` for `en`)
- `letters`: a regular expression for the letters of the language, used to reject copied Italian (for `eo` and `en`, which share the Latin script, it rejects only lines without letters; a verbatim copy is still rejected)
- `closing`: the word that opens the heading of the closing section (`Επίλογος` for `el`, `Epilogo` for `eo`, `Epilogue` for `en`)
- `note`: an extra instruction added to both prompts (for `el`, to use the monotonic orthography; for `eo`, to write the letters with diacritics, not in the x- or h-system; for `en`, to write curly quotation marks, not straight ones, and the apostrophe as the straight `'`, so that `’` always closes a `‘`)

## scripts/fix_quote_blocks.py

```bash
uv run scripts/fix_quote_blocks.py -d DIR [-d DIR ...] [-n]
```

argument | description | default
---|---|---
`-d`, `--dir` | directory holding `<canticle>/<NN>.md` (repeatable) | required
`-s`, `--source` | source text of the quoted originals: `it`, `grc`, or `carlyle` (whose quotes have no translation line, so only the originals are rebuilt) | `it`
`-t`, `--translations` | directory holding `<canticle>/<NN>.txt` | next to each `<NN>.md`
`-n`, `--dry-run` | report the files that would change without writing them | write

The model tends to drop the two trailing spaces that make each quoted original a line of its own in Markdown, and may quote a line slightly differently from the corpus. This script rebuilds every quote block of each `<canticle>/<NN>.md` from the sources of truth: for each `> N ...` line followed by a `> (...)` line, the original is replaced by line N of dante-corpus, with two trailing spaces, and the translation by line N of the sibling `<NN>.txt`:

```markdown
> 1 Nel mezzo del cammin di nostra vita  
> (Στη μέση του δρόμου της ζωής μας)
>
> 2 mi ritrovai per una selva oscura,  
> (βρέθηκα μέσα σε ένα σκοτεινό δάσος,)
```

A separator line (`>` alone) is inserted between two pairs that have none; existing separators, skipped lines, and anything else in the block are kept. A file without a sibling `.txt`, a pair without a translation line, or a line number out of range is left as-is with a warning. The model is not called, so the script can be run any number of times.

## scripts/check_quotes.py

```bash
uv run scripts/check_quotes.py [canticle ...] -l CODE -d DIR [-c SPEC] [-s SOURCE]
```

argument | description | default
---|---|---
`canticle` | canticles to check | all
`-d`, `--dir` | directory holding `<canticle>/<NN>.txt` | required
`-c`, `--canto` | cantos to check (SPEC syntax) | all
`-s`, `--source` | source text the translations follow: `it` or `grc` | `it`

Each line is translated on its own, so the model may drop or add a quotation mark where a speech opens or closes on a line of its own. This script compares the quotation marks of each `<NN>.txt` with the original. The original nests its quotes as `«»` > `“”` > `‘’`, while the translation writes them mostly as `«»`, so the kind of mark is not compared; instead the nesting depth (opening marks minus closing marks, counted from the start of the canto) is compared at the end of every line. In the translation `’` is the apostrophe of elision (`γι’`, `απ’`), so only `«»` and `“”` are counted there.

The translation must follow the original line by line, even at the cost of a forced word order, so each run of consecutive lines whose depths differ is reported as a mismatch: a mark is missing or extra (the difference is then carried on to the end of the speech or the canto), or the translation's word order has moved a quote boundary to a neighbouring line.

With `-s grc`, the marks are compared line by line instead. Musurus's Greek opens a speech with `“`, closes it with `”` or `“`, and opens every line inside it with `„` (`‚ „` inside a quote within a speech, which opens with `‘“` and closes with `”’`), so the depth cannot be counted from the marks alone. The translation writes the same marks, so each line must hold the same sequence of marks as its original: `“”«»` count as one kind, and `’` after a letter is an apostrophe of elision. Each run of lines whose sequences differ is reported.

The exit status is 1 if there is a mismatch. The model is not called; mismatches are fixed by hand in `<NN>.txt`. A missing or extra mark is added or removed without touching the wording. When an inner quote of the original (`“”`, `‘’`) inside a speech is written as `«»` and the depths no longer match, it is written as `“”` instead. A moved boundary is fixed by rewording the lines so that each holds what its original line holds, as in Inferno 13.133-134:

```
«O Iacopo», dicea, «da Santo Andrea,
che t'è giovato di me fare schermo?

«Ω Ιάκοπο», έλεγε, «ντα Σαντ’ Αντρέα,
τι κέρδισες που με έκανες ασπίδα σου;
```

## scripts/check_lines.py

```bash
uv run scripts/check_lines.py [canticle ...] -m MODEL -l CODE -d DIR -o OUT [-c SPEC] [-s SOURCE] [--no-think] [--save-usage]
uv run scripts/check_lines.py [canticle ...] -r -d DIR -o OUT [-c SPEC] [-s SOURCE] [-k KIND ...]
uv run scripts/check_lines.py [canticle ...] -a -k KIND [-k KIND ...] -l CODE -d DIR -o OUT [-c SPEC] [-s SOURCE]
```

argument | description | default
---|---|---
`canticle` | canticles to check | all
`-c`, `--canto` | cantos to check (SPEC syntax) | all
`-m`, `--model` | model name with an optional vendor prefix | required to ask the model
`-l`, `--lang-code` | language code of the target language | required to ask the model or to apply
`-d`, `--dir` | directory holding `<canticle>/<NN>.txt` | required
`-o`, `--out` | directory for the saved answers, `<out>/<canticle>/<NN>.json` | required
`-s`, `--source` | source text the translations follow: `it` or `grc` | `it`
`-r`, `--report` | only report the saved answers, without calling the model | -
`-a`, `--apply` | apply the fixes of the saved, up-to-date answers, without calling the model | -
`-k`, `--kind` | report or apply only issues of this kind (repeatable) | all to report; required to apply
`--no-think` | disable thinking output | enabled
`--save-usage` | record usage for any model | -

From the Makefile:

```bash
make check-lines CANTICLE=inferno CANTO=1-3   # ask the model; all cantos if both are omitted
make check-lines CHECK_MODEL=<model>          # ask another model than the one that generated the texts
make report-lines KIND="moved missing"        # report the saved answers and their fixes; all kinds if KIND is omitted
make apply-lines KIND=moved CANTO=1-3 CANTICLE=inferno   # apply the saved fixes of the given kinds
```

The translation must hold, on each line, what the original holds on that line and nothing from its neighbours, even at the cost of a forced word order. `check_quotes.py` catches this only where a quote opens or closes; whether a phrase has crossed a line break elsewhere is a matter of meaning, so this script asks the model. For each canto it sends every original line followed by its translation, and asks for every place that breaks this, classified by kind:

kind | meaning
---|---
`moved` | a content word or phrase of one original line rendered on another line
`function` | a function word, auxiliary verb, clitic pronoun, or degree word rendered on another line; often forced by the grammar of the target language (a clitic goes with its verb), but sometimes not (a compound tense split over two lines can be split the same way in Greek)
`missing` | part of a line's content not rendered
`added` | content in the translation that belongs to no line

Word choice, style, and the order of words inside a line are not reported. Nothing else is excluded at report time, not even the `function` cases the grammar seems to force: whether to fix each one is decided afterwards, against the original.

For each issue the model also gives a fix: the rewritten translation of every line involved. It is left empty where the lines cannot follow the original without breaking the grammar, and the problem then says why.

Each answer is saved as `<out>/<canticle>/<NN>.json` (`check/el/` from the Makefile), with the model and the translation it was given. The Makefile asks `CHECK_MODEL`, which defaults to `MODEL` and can be set on the command line, e.g. to check with a lighter model. A canto whose saved translation still matches its `.txt` is not sent again, so a run can be resumed, and after fixing a few `.txt` files only those cantos are asked anew. Every saved answer is reported at the end as `<path>: <lines> [<kind>]: <problem>`, followed by its fix as `-` (current) and `+` (proposed) lines, and marked `(stale)` if the `.txt` has changed since.

`--apply` writes the fixes of the given kinds into the `.txt` files, from up-to-date answers only. A fix is skipped, with the reason, if it:

- rewrites a line that is not one of its issue's lines
- leaves a rewritten line without a letter of the target language
- makes the quote marks stop following the original (as `check_quotes.py` checks them)
- touches a line that a fix applied before it in the same canto has already changed
- is empty

The workflow is:

1. `make check-lines`, then `make report-lines` to read the issues and their fixes against the original.
2. `make apply-lines KIND=...` for the kinds to take; a fix that should not be taken is reverted by hand (or the `.txt` edited by hand instead).
3. Review the result with `git diff`, and run `make check-quotes`.
4. `make check-lines` again: only the changed cantos are asked anew.
5. When the translations are done, `make fix-quotes` to sync the commentaries.

Only the `.txt` files are read; the commentaries are synced only at the end.
